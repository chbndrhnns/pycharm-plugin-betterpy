MCP agent testing harness¶

scripts/mcp_agent_harness.py runs real MCP contract checks and Junie ACP scenarios against BetterPy. It uses Python's standard library; no browser or mouse automation is required. This is an opt-in live suite, separate from ordinary unit tests. Model availability and agent behavior can fail independently of the plugin.

The initial suite covers:

  • Discovery: ask for implementations of a Python class without naming the MCP tool; require One and Two at their expected source locations in the raw tool result.
  • Missing target: require BetterPy's expected class-not-found error, rather than accepting any error as success.
  • Refactoring: ask for dictionary bracket access to become .get(); require exactly one successful semantic transformation and an exact on-disk result.

Each scenario runs against a disposable Python project, after a direct MCP baseline. The agent sees the IDE's real tool inventory. An observing proxy permits only the scenario's expected tool and file arguments; all other MCP operations that could invoke tools are denied. Junie runs in Safe mode, and the ACP client denies terminal/file operations and unrelated permissions. The harness does not invoke SaveAll, modify the user's MCP configuration, or silently change models.

Existing IDE¶

Use a dev BetterPy build with remote control enabled, a Python 3.11+ interpreter, installed Junie CLI, and an authenticated Junie account. Copy BetterPy's connection environment from the IDE, then set the global MCP server's Streamable HTTP URL separately:

export BETTERPY_REMOTE_BASE='http://127.0.0.1:<remote-port>/api/betterpy-remote'
export BETTERPY_REMOTE_TOKEN='<session-token>'
export BETTERPY_MCP_URL='http://127.0.0.1:<mcp-port>/stream'
python3 scripts/mcp_agent_harness.py --attach --model gpt-6-luna

The remote-control token is not an MCP credential. Air's private authenticated MCP service is also different from the global MCP service. Attach mode currently expects a loopback global MCP endpoint that does not require additional authentication.

The harness addresses its project explicitly without changing the remote-control project pin. It closes and removes that project on completion. The SDK may remain in an attached IDE's SDK table; isolated launch avoids this residue.

Isolated 263 EAP launch (macOS)¶

Provide the installed PyCharm .app and plugin distribution directories. Plugin directories are copied, not modified. BetterPy must be a dev build. Include Air if the IDE does not bundle it. Junie CLI uses its existing account authentication; no login data is copied from IDE settings.

python3 scripts/mcp_agent_harness.py \
  --ide-path '/path/to/PyCharm 2026.3 EAP.app' \
  --plugin-dir '/path/to/plugins/betterpy' \
  --plugin-dir '/path/to/plugins/air-plugin' \
  --model gpt-6-luna

The harness creates separate config, system, log, and plugin directories; assigns free loopback ports; enables MCP in that sandbox; and verifies the loaded BetterPy JAR hash. It stops only the process group it started. It does not build the plugin: build/install the intended distribution first. Ordinary attached runs record the loaded artifact hash without asserting it equals the working tree.

Useful runs¶

# Fast deterministic contract checks, no model inference
python3 scripts/mcp_agent_harness.py --attach --direct-only

# Repeated independent refactoring attempts; any failure keeps a nonzero exit
python3 scripts/mcp_agent_harness.py --attach --scenario refactor --repeat 3

# Explicit Lite selection; unavailable/rate-limited Lite does not fall back to a paid model
python3 scripts/mcp_agent_harness.py --attach --model junie-lite --agent-timeout 60

# Tests of transport/policy/ACP failure handling; no IDE or model account needed
python3 -m unittest discover -s scripts/tests -p test_mcp_agent_harness.py -v

--model accepts an advertised model suffix or full ACP identifier. Ambiguous/unavailable selections fail. --python selects the local interpreter for the fixture venv. --scenario is repeatable. --agent-timeout bounds each ACP request; timeouts send session/cancel and terminate/reap the owned CLI process. A visible provider 429 is classified separately from a generic agent timeout.

Evidence and interpretation¶

Each run gets a unique private directory under build/mcp-harness/ (override with --output). report.json is the overall result and the process exits nonzero on failed assertions, setup, transport, or cleanup. Attempts are never retried into a green result.

Artifacts include IDE identity and plugin hash, actual MCP inventory, direct baseline requests/results, per-scenario raw MCP and ACP NDJSON, selected model and agent version, before/expected/after source, source hashes, document/disk timeline, final answer and usage, and cleanup outcome. Account identity notifications and connection headers are excluded from traces. Junie stderr and isolated IDE logs remain diagnostic artifacts: treat output directories as local/private rather than publishing them without review.

Assertions distinguish tool execution from persistence: a successful MCP response or plausible model answer is insufficient when the file differs. Source hashes cover the disposable project; .idea and .venv metadata are excluded. These checks do not claim to monitor arbitrary writes elsewhere on the machine. Default Junie config/MCP/skill locations are disabled, but Junie may still load built-in context or use auxiliary routing/summary models; the selected model identifies the primary agent.

Early experiments found that SDK presence and smart mode alone did not guarantee usable Python types. The harness creates an explicit absolute content root, configures the SDK, reopens the fixture, and requires a direct semantic baseline before agent evaluation. One earlier probe returned transformed text while disk retained the original. Later instrumented/open-editor and closed-editor controls passed; the cause was not established. Persistence assertions and retained failure evidence are intentional.

The isolated IDE sandbox and logs are retained for debugging; the fixture is removed after closing. The per-run token-bearing VM options file is removed after shutdown. Delete old output directories when their evidence is no longer needed. No scheduling, publishing, or CI release gate is installed by this script.

Mutation requests are reserved before forwarding: if an upstream response times out, the harness refuses another mutation because the first may still complete. This matters for dict_access, which toggles between bracket and .get() access. Diagnostic sampling errors are recorded separately from the actual MCP response and fail the run without rewriting a successful tool response as a transport error. Isolated launches suppress the startup splash; unexpected modals remain failures. The one handled connection prompt is Junie’s optional broad IDE RPC connection: the harness clicks Deny only when the dialog identifies its owned Junie process group and exact ACP command. This keeps agent access on the restricted MCP path.
