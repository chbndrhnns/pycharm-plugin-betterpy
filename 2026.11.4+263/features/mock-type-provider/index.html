Mock type provider¶

Since 2026.08.0 · Maturity Stable · Default Enabled · Settings Settings → BetterPy → Testing → Mocking

Provides type information for unittest.mock objects, improving code completion and type checking for mocked values. With the default-on Validate arguments when spec is a class setting, calls through Mock(spec=Service) or class-based Mock(spec_set=Service) are checked against the class's method signatures, even without autospec=True. Recorded method-call assertions are checked too, including on subclasses of Mock. A method's return_value child is not treated as another instance of the original class spec for assertion validation. Class patches with spec=True or spec=Service receive the same checks. Disable the option in Settings → BetterPy → Testing → Mocking → Mock type provider, or use the contextual tip shown near a class-based spec. This changes BetterPy's analysis only; Python's runtime spec behavior is unchanged. Autospec validation is unaffected when this option is disabled. For patch.object(..., autospec=True), calls through an instance use the bound method signature: pm.method(value) omits the implicit receiver and reports arguments the method does not declare. The assertion method compares recorded call arguments, so class-patched instance methods include the receiver in assert_called_once_with. These checks also apply to injected decorator parameters and with patch.object(...) as mock_method aliases. For a class target, use mock_method.assert_called_once_with(instance, value); for an instance target, use mock_method.assert_called_once_with(value). Stacked decorators inject mocks bottom-up before pytest fixture parameters. Without autospec=True, alias assertion arguments remain unconstrained. For @patch("package.module.Class", autospec=True), instances constructed through the patched module binding (for example, module.Class()) expose mock helpers such as assert_called_once_with and retain autospecced call-argument checks. An alias imported before patching with from package.module import Class still refers to the original class and is not treated as a mock.

Class and instance patch examples¶

These four tests can live in tests/test_m.py. Enable Mock type provider for mock inference and autospecced call-argument checks; Mock assertion methods provides focused assertion-helper support. At runtime, plain patches accept arbitrary call arguments, while autospecced patches enforce the original signature.

Every example calls method_to_mock("value") once, checks that it returns "mocked result", and verifies that same recorded call. All four tests pass; only the patch setup and the explicit receiver in the class-method autospec assertion differ. Invalid-argument cases are discussed separately below, not mixed into these examples.

from unittest.mock import patch

class PatchMe:
    def method_to_mock(self, arg): ...

@patch.object(PatchMe, "method_to_mock")
def test_patch(mockable_method):
    mockable_method.return_value = "mocked result"
    pm = PatchMe()

    assert pm.method_to_mock("value") == "mocked result"
    pm.method_to_mock.assert_called_once_with("value")

@patch.object(PatchMe, "method_to_mock", autospec=True)
def test_patch_autospec_method_on_class(mockable_method):
    mockable_method.return_value = "mocked result"
    pm = PatchMe()

    assert pm.method_to_mock("value") == "mocked result"
    # The class target is unbound: recorded calls include the instance.
    mockable_method.assert_called_once_with(pm, "value")

def test_patch_autospec_instance():
    pm = PatchMe()
    with patch.object(pm, "method_to_mock", autospec=True) as mockable_method:
        mockable_method.return_value = "mocked result"

        assert pm.method_to_mock("value") == "mocked result"
        # The instance target is already bound: no explicit self.
        mockable_method.assert_called_once_with("value")

@patch("tests.test_m.PatchMe", autospec=True)
def test_patch_autospec_class(mock_patch_me_class):
    mock_instance = mock_patch_me_class.return_value
    mock_instance.method_to_mock.return_value = "mocked result"
    pm = PatchMe()

    assert pm.method_to_mock("value") == "mocked result"
    pm.method_to_mock.assert_called_once_with("value")

Both autospecced method patches reject pm.method_to_mock("value", 1) with TypeError: the original method accepts one explicit argument. Patching the class itself makes its return_value the constructed mock instance; its method assertions do not include self. Adjust the string target to your module, and patch the name where the tested code looks it up—not a different module's previously imported alias.

Validating callable side effects¶

The default-on Validate callable side effects against patched implementations setting checks callable side_effect values in recognized patch(...), patch.object(...), and pytest-mock patch calls when spec or spec_set is active. It compares accepted arguments and return types with the original patched callable, not an explicitly supplied alternative spec. For example, a broader input and narrower compatible output are accepted, while incompatible parameters or return types are highlighted on the side_effect value:

from unittest.mock import patch

class UserStore:
    @staticmethod
    def fetch(user_id: int) -> int: ...

def compatible(user_id: object) -> bool: ...
def wrong_parameter(user_id: str) -> int: ...
def wrong_return(user_id: int) -> str: ...

patch.object(UserStore, "fetch", spec=True, side_effect=compatible)  # accepted
patch.object(UserStore, "fetch", spec=True, side_effect=wrong_parameter)  # incompatible parameter
patch.object(UserStore, "fetch", spec_set=True, side_effect=wrong_return)  # incompatible return

The inspection accounts for defaults, positional-only and keyword-only parameters, *args, **kwargs, bound receivers, and awaited results for async targets with async side effects. It reports only provable incompatibilities; exception and iterable side effects, unresolved targets, unknown or ambiguous types, and autospec-only patches are skipped. Direct Mock(...) constructors and later .side_effect assignments are outside its scope. Turn off Validate callable side effects against patched implementations in Settings → BetterPy → Testing → Mocking → Mock type provider to suppress these additional diagnostics without changing mock inference or the class-spec argument checks above.
