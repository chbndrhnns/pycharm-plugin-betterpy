Move Refactorings¶

BetterPy contains several move-oriented refactorings. They are currently exposed through intentions and refactoring menu actions rather than one unified Move dialog.

Use this page as the overview for choosing the right move operation.

Quick Reference¶

Refactoring Main Use Case Invocation Current Entry Point
Move to inner scope Move a top-level function or class into another class in the same file ⌥⏎ / Alt+Enter on the function or class name Intention
Move to outer scope Move a nested class, local function, or method outward ⌥⏎ / Alt+Enter on the class or function name Intention
Move test to another class Move a pytest test method into another or new test class Refactoring menu action or intention, depending on context Refactoring action
Pull up pytest fixture Widen a fixture's availability Refactoring menu action on a fixture Refactoring action
Push down pytest fixture Narrow a fixture's availability Refactoring menu action on a fixture Refactoring action
Move declarations Move top-level Python declarations to another module with import updates Implemented as a move handler/dialog, but not currently registered by a feature fragment Internal/prototype

Move To Inner Scope¶

Moves a top-level declaration into another top-level class in the same file.

Supported source declarations:

  • Top-level function to method.
  • Top-level class to nested class.

Function To Method¶

If the function's first parameter is annotated with the target class, BetterPy turns that parameter into self and rewrites call sites from function calls to method calls.

class User:
    pass

def display_name(user: User) -> str:
    return "Alice"

result = display_name(User())

class User:
    def display_name(self) -> str:
        return "Alice"

result = User().display_name()

If the function does not have a class-typed first parameter, BetterPy moves it as a static method and rewrites simple call sites to ClassName.method(...).

class User:
    pass

def format_name(value: str) -> str:
    return value.title()

result = format_name("alice")

class User:
    @staticmethod
    def format_name(value: str) -> str:
        return value.title()

result = User.format_name("alice")

When more than one target class is available, BetterPy chooses the class named by the first parameter annotation when that match is unique. Otherwise it shows a chooser.

Class To Nested Class¶

Moves a top-level class into another top-level class, preserving the class body and updating unqualified references outside the target class to TargetClass.MovedClass.

class Container:
    pass

class Item:
    pass

value = Item()

class Container:
    class Item:
        pass

value = Container.Item()

Availability And Guards¶

  • The caret must be on the function or class name.
  • The source declaration must be top-level.
  • At least one valid target class must exist in the same file.
  • BetterPy does not offer the move if it would create a name collision in the target class.

Move To Outer Scope¶

Moves a declaration out of a narrower Python scope.

Supported source declarations:

  • Nested class to the containing class's parent scope, or to module level.
  • Local function to module level.
  • Instance method to top-level function.

Nested Class To Outer Scope¶

Moves a nested class one level outward and updates references in the file.

BetterPy blocks the move when the target scope already contains a class with the same name, or when the nested class references members of the outer class in a way that would be unsafe after the move.

Local Function To Top Level¶

Moves a function defined inside another function to module level. If the local function reads variables from the outer function, BetterPy adds those captured names as parameters and updates calls in the outer function.

def outer(prefix: str):
    def build(value: str) -> str:
        return prefix + value

    return build("x")

def build(value: str, prefix: str) -> str:
    return prefix + value

def outer(prefix: str):
    return build("x", prefix)

BetterPy does not offer this move when the local function uses nonlocal or is returned/stored as a closure while depending on captured variables.

Method To Top-Level Function¶

Moves an instance method to module level. The first self parameter becomes typed with the source class, and call sites are rewritten from obj.method(args) to method(obj, args).

class User:
    def display_name(self) -> str:
        return "Alice"

user = User()
result = user.display_name()

def display_name(self: User) -> str:
    return "Alice"

class User:
    pass

user = User()
result = display_name(user)

BetterPy does not offer this move for @staticmethod, @classmethod, @property, dunder methods, methods without self, or methods that call super().

Move Test To Another Class¶

Moves a pytest test method from one class to another existing test class, or into a newly created class.

Use this when a test method is in the wrong test grouping but should remain a method.

Behavior:

  • The source function must be a pytest test method inside a class.
  • BetterPy proposes a class name from the test function name when creating a new class.
  • Existing target classes are filtered to avoid method name collisions.
  • Moving into an existing class preserves method style.
  • Moving to a new class inserts the new class near the source class and leaves pass in the source class if it becomes empty.

Pull Up Pytest Fixture¶

Moves a fixture to a wider pytest scope.

Supported directions:

  • Class fixture to module-level fixture in the same file.
  • Module-level fixture in a test file to conftest.py in the same directory.
  • Fixture in conftest.py to the parent directory's conftest.py.

BetterPy creates the target conftest.py when needed and copies relevant imports. The move is blocked if the target already defines a fixture with the same effective fixture name.

Push Down Pytest Fixture¶

Moves or copies a fixture to a narrower pytest scope.

Supported directions:

  • Fixture in conftest.py to a single child directory's conftest.py.
  • Module-level fixture in a non-conftest.py file into one or more test classes in the same file.

For conftest push-down, BetterPy requires exactly one child directory. Multiple child directories are ambiguous, so the action is not offered.

For class push-down, BetterPy adds self when converting the fixture function into a fixture method. If several test classes are available, it shows a chooser.

If the source fixture is still used outside the target scope, BetterPy keeps the original fixture and copies it into the target instead of deleting it.

Move Declarations¶

The repository contains an implementation for moving top-level Python declarations to another module:

  • supported source elements are top-level functions and top-level classes;
  • the dialog asks for a dotted target module path;
  • the processor creates packages/modules when needed;
  • references are searched and updated for common import/reference forms;
  • remaining usages in the source file receive an import from the new module.

Current status: this implementation exists under features/refactoring/move, but it is not currently registered by a feature XML fragment. Treat it as implementation groundwork rather than a user-visible feature until it is explicitly wired into the plugin.

Known UX Gap¶

These moves are related, but they are not yet unified behind the standard Refactor -> Move... action. A future unification should add one BetterPy MoveHandlerDelegate that is ordered before PyCharm's Python move handler, returns false for unsupported contexts, and dispatches to the existing move processors.
