<!-- Plugin description -->
**BetterPy** supercharges your Python development in PyCharm and IntelliJ-based IDEs — so you can spend less time on boilerplate and more time building.

BetterPy was created out of a personal need to improve my daily workflow.
I had been using PyCharm for more than 8 years and found myself constantly repeating the same actions,
which were time-consuming and frustrating.
I wanted to streamline my workflow and make development more efficient.
First, I went to the issue tracker to report what I found. Later, I found that my priorities did not always align with
the PyCharm product manager's roadmap.
I decided to take matters into my own hands and started working on BetterPy to address the issues I encountered.

My main goals are to:

- **Automate repeated actions** that otherwise take too much clicking around.
- **Fix annoying behavior** and smooth out workflow friction.
- **Extend PyCharm** based on personal and practical development needs.

The areas of PyCharm I am adressing with the plugin are naturally aligned with the scope of my development activites,
which are API backend development, domain-driven design and automated testing.

#### Reporting Bugs: Collecting Diagnostic Data

To help triage and fix issues quickly, please attach diagnostic data to every bug report. **Issues opened without this information are subject to being auto-closed.**

BetterPy can open GitHub with diagnostic data already attached:

1. Click the **BetterPy** icon in the IDE status bar (bottom-right).
2. Choose **Create GitHub Issue...** from the popup.
3. Complete the bug report in GitHub.

If the diagnostic data is too large for GitHub's issue URL, BetterPy copies it to your clipboard and opens the bug report without prefilled diagnostics. Paste the copied data into the diagnostic data field.

If you are editing an existing issue or need the data separately, choose **Copy Diagnostic Data** from the same popup and paste the contents manually.

This captures the IDE build, BetterPy version, OS, Python/SDK info, and the relevant BetterPy settings.

In addition, please include:

- **Steps to reproduce** — a minimal Python snippet, the exact menu/shortcut/intention used, caret position if relevant, and expected vs. actual behavior.
- **Screenshots or short screen recordings** for UI-related issues (optional but very helpful).
- **Stack traces** — if the IDE shows a red error icon (Internal Error) in the status bar, click it and copy the full stack trace into the issue.
- **`idea.log`** if the problem is not reproducible from the snippet alone — collect it via **Help → Collect Logs and Diagnostic Data**.

> ⚠️ Please review log files and snippets for anything sensitive (paths, tokens, proprietary code) before posting them publicly.

Issues filed without enough information to reproduce or diagnose the problem may be closed automatically after a reminder.
